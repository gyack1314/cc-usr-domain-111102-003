# 优惠分摊与复式账簿

workbench/book.py在SQLite事务内提供销售入账、退货、冲正与核对四个接口，账户方向与税额包含关系遵循docs/domain.md。所有金额为币种最小单位整数，每笔分录按币种借贷相等，不同币种不互相抵销。

## 分摊规则

- 订单级优惠按各行优惠前金额比例分摊到商品行，余数用最大余数法，余数相同按line_id升序；零价行权重为零，不承接按金额分摊的优惠。
- 行优惠后实收与行税额在同一层次独立分到带unit_no的单件单位（单位权重相同，余数按unit_no升序）。
- 优惠后实收须不小于总税额，且任一行分摊后net<tax，或优惠没有可承接的合法金额，整单拒绝，不产生任何记录。
- 每个单位的(net,tax)权益在入账时冻结；退货只取冻结值，不按退货时的价格或税率重算，因此拆退顺序不会改变总退款。

## 分录方向

- 销售：借cash=实收，贷revenue=实收-税额，贷tax_payable=税额。
- 退货：贷cash=退款，借revenue=退款-退税，借tax_payable=退税。
- 冲正：引用原退货分录逐项反向，不删除旧账；entries.reverses的唯一索引保证同一分录只能被冲正一次。

entries记录kind/store/sale_id/request_id，entry_units记录退货覆盖的单位，原单与退款链可逐级追溯（`python -m workbench.cli entry 库 分录号`）。

## 退货语义

- 请求按原line_id和累计退货数量申请；未指定unit_no时固定取该行尚未退的最小编号单位，也可显式给出unit_no数组。
- 同一request_id同内容返回原回执，内容不同报冲突（退出码3）；失败请求整体回滚、不落库，可同号重试。
- BEGIN IMMEDIATE配合条件UPDATE（仅当单位仍在售才占用），多进程竞争最后一个可退单位只有一笔成功。

## 核对

reconcile不凭借贷平衡宣称正确，而是同时验证：

1. 每笔分录分币种借贷平衡，且单分录不混币种；
2. 行分摊合回原单实收、优惠、税款，单位分摊合回行金额；
3. 实际权益占用：每个单位要么在售，要么被唯一一笔未冲正的退货分录按冻结金额占用；
4. 账户余额与未退权益占用逐币种相等（cash=未退实收，tax_payable=未退税额，revenue=差额）；
5. 请求-分录-原单链完整，冲正分录引用真实退货分录。

`python -m workbench.cli reconcile 库`打印报告，核对不通过时退出码为1。`python -m workbench.cli demo 新库路径`用samples中的合成单据演示拆退、整退、冲正、幂等重放与进程重开，全部资料为本地合成，没有支付网关调用。
